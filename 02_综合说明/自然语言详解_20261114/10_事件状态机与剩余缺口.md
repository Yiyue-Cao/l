# 事件状态、验证范围与剩余缺口

规则详见 [19 个策略索引](../../01_策略库与详细解读/19个策略_数学化还原索引.md)。本篇统一说明验证单位和复原边界；语言精修未新增二进制实验。

## 关键状态与失败行为

| 策略/范围 | 必须保留的行为 | 错误的简化会造成什么差异 |
|---|---|---|
| Comm 系列 | 正价格和单向 1 秒时效检查；未来盘口不被这条检查拒绝 | 使用绝对时间差会改变早退条件 |
| 10 个 touch 库 | 订单请求接受后才写 touch；拒绝时不写；行情变价删除 | 下单前写门控会把拒单后的下一次尝试堵住 |
| SM3.1 | A 覆盖旧 A，B/行情先移除待处理 A，再决定交易 | 失败回滚 A 会造成原程序没有的重复决策 |
| SM3.1 | 超时由行情驱动，并在毫秒差上加 1e-6 | 增设后台计时器或省略 epsilon 会改变顺序和边界 |
| LF4 | 首次请求之前已插入任务，失败不撤回；重试没有递增次数槽或重新置位行情标志 | 机械实现“最多重试 N 次”会偏离当前二进制 |
| TM5/TM6 | 订单回调累计，行情回调按 SDK 时间淘汰并发布 | 在订单回调立即 publish，会改变 watcher 所见值 |
| SoS5/SoS6 | 账户快照存在时覆盖 free_cash；阶段先改，随后交易失败不恢复 | 只用收益切阶段或按发单成功提交阶段都会不同 |
| SoS5/SoS6 | 已测普通交易路径没有调用 SDK impact_block_check | 套用其他库的公共风险过滤流程会多出阻断 |
| SoS6 | 四个阈值键都读取，全部存在才整体更新 | 单键就更新/缺键补零会改变有效阈值 |
| comm_mock | 回报累计后，下一条行情发布七个品种键；ntrade 按有效回报条数 | 用成交手数代替笔数、即时发布都不等价 |
| SM2 | 特定合成输入可触发 utility op without price 的原始断言 | 将 panic 吞成无动作会掩盖真实失败分支 |
| TM6 | 阈值发布先于后续撤单/订单结果 | 错误时回滚已发布阈值会改变 SoS 订阅链 |

## 挂单、候选树与 XS 验证

| 项目 | 验证范围 | 结论 |
|---|---:|---|
| 非空挂单辅助函数 | 12 库各 85 场景，共 1020 | 撤单两遍顺序、首个错误停止、成功 ID 不回滚、排除集合、按订单条数计数 |
| 全库原始信号回调 | 19 库各 36 场景，共 684 | 区分 SDK 批量撤单路径与逐 ID 路径；分别记录发单和失败 |
| LOW maker 回调 | 7 库各 18 场景，另各场景 5 次暖启动 | 存活本向单阻断、已提交撤销 ID 排除、失败不发单 |

| SM4/TM6 候选树 | 各 2400 事件 | 每候选完整配对队列及选择键逐步对照，含多合约和时间倒退 |

| comm5 XS 实际订单 | 32 回调 | 倍率与金额到手数贯通；零倍率只在开仓动作另设门控，明确平仓可执行 |

除脚本内部的逐步模型断言外，本地又对最终回执做 **806 项结果检查，全部通过**。前轮 1186 个回调重新运行，1111 项既有断言全部通过；这部分是回归，不算新增。新的失败场景按“预期原始 panic 被复现”记录，不能和正常返回混计。

## 基础回调与状态序列验证

验证加载原始 Linux x86-64 二进制，调用其初始化与业务回调。SDK 使用 ABI 经汇编核对的本进程桩，提供合成行情、时间、持仓、发布值与返回码；订单仅被记录，无真实交易、Slurm 或行情回测。没有使用独立验证集。

| 类别 | 场景或序列中的回调数 | 覆盖内容 |
|---|---:|---|
| 19 库 × 18 个独立信号场景 | 342 | 信号/合约过滤、时段、盘口、时效、买卖、撤单/订单错误、非负返回码、风险过滤 |
| 10 库 touch 序列 | 540 | 成功/拒绝、同盘口、价格变化、NaN、正/零/负超时、浮点边界 |
| SM3.1 A/B 正常与失败序列 | 23 | 覆盖等待 A、B 复用、未来 B、行情超时、先消费再失败 |
| LF4 目标任务序列 | 24 | 首次失败保留任务、行情复位、重复重试、持仓更新、截止边界 |
| TM5/TM6 收益队列 | 18 | 订单追加、零数量忽略、窗口等号、SDK 时钟和行情字段分离 |
| SoS5/SoS6 阶段边界 | 216 | 三初态、收益边界、账户正负零、快照覆盖 free_cash |
| SoS6 四阈值存在性组合 | 16 | 全部有/无组合、读键顺序、整组更新 |
| comm_mock 回报与发布 | 7 | 收益/金额/笔数累计、下一行情发布、零数量忽略 |
| 合计 | 1186 | 含一个 SM2 原始 panic 场景 |

其中 1111 项显式状态/顺序断言通过。断言、独立场景、序列事件是三个不同口径；不把它们和既有 56740 个叶函数/报价检查相加。342 个独立信号场景中，341 个正常返回到调用脚本，另一个 SM2 子进程因原始 panic 退出 134。正常返回包括 `Result::Err` 错误返回，并不都代表成功下单。

## 复原边界

目前可以据文档实现主要信号、报价与本轮明确验证的状态机，并使用原始二进制作为测试参照。仍不能宣称已经有一个完整可替换插件，原因是以下部分尚未端到端闭合：

- 真实 SDK 的撮合、费用、在途预占、部分成交和回报排列，以及跨日账户接续。
- 已验收非空列表、逐 ID 混合失败、部分成交列表状态；仍缺真实 SDK 成交/撤销回报与账户预占交错的联合回放。
- comm4/4.1/5 的阶段切换、挂单、交易次数与真实账户联合长序列；comm5 XS 的独立排名和开平动作已验证，历史实际收益文件和配置尚未恢复。
- SM4/TM6 大候选集合造成多层 BTreeMap、极端非有限值及候选统计与真实收益发布联合回放。已逐个检查小候选集合的配对队列，并非仅根对象字节比较。
- SoS5 四品种实时参考价拒收及跨合约 section 迁移；SoS6 多键发布的原子性由外部 SDK 决定。
- SM2 的完整数值尾部分支和插件包装层对 panic 的最终处理。
- 历史加密配置明文与上游预测信号公式。

上述缺口已分别放入每篇策略文档，并区分已做的原始回调实测、静态证据和仍未闭合的组合。具体参数是否重要取决于分支：例如 LF4 的期限、SM3.1 的模式开关、SoS 的阶段条件会改变状态机，不能一概作为“只是参数”忽略。
