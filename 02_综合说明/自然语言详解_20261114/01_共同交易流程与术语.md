# 共同交易流程与符号

19 个库接收外部信号、行情和账户事件，输出订单、撤单或发布值。上游预测、策略决策、实验驱动、撮合账户分别属于不同层。

## 层次与输入输出

| 层次 | 输入 | 输出 |
|---|---|---|
| 预测系统 | 上游数据与模型 | 信号事件；具体预测公式尚未恢复 |
| run 驱动 | 基础配置、参数组合、日期、路径 | 具体配置与 runner 调用 |
| 策略 `.so` | 事件、本地状态、SDK 上下文 | 状态变化、订单／撤单／发布请求 |
| SDK 与引擎 | 请求、盘口、账户与撮合规则 | 请求结果、成交及账户回报 |

驱动支持某参数不代表历史实验启用它；策略提出请求也不代表已经成交。

## 统一的回调描述

$$F(S,e,c)=(S',R,\rho).$$

$S$ 为本地状态，$e$ 为事件，$c$ 为 SDK 上下文，$S'$ 为更新后状态，$R$ 为有序请求／发布序列，$\rho$ 为正常返回、错误或 panic。复原应同时比较三项输出，而非只比较订单或收益。

通常需处理事件适用性、信号与阈值、风险过滤、报价、挂单和数量。但各库次序不同，必须按逐库回调链实现。尤其是 $\rho=\mathrm{Err}$ 时仍可能有 $S'\ne S$：失败不会统一撤回已写状态。

## 动作、报价与请求

| 符号／编码 | 含义 |
|---|---|
| $T=(L_o,L_c,S_o,S_c)$ | 开多、平多、开空、平空门槛 |
| $A=0,1,2,3,4$ | 开多、平多、开空、平空、无动作 |
| $Q=0,1,2,3$ | 对应报价函数中的 Taker、Maker、Mid、Skip |
| $q,v,p,M$ | 当前持仓、请求量、请求价、合约乘数 |

$q,v$ 的正负分别表示多／买与空／卖。开仓动作可包含回补反向仓位，纯平仓量则受旧仓限制。动作判断有先后，重叠阈值不自动排序；SM2 先选效用侧，另有分类顺序。

Maker/Taker 描述报价意图；IOC/IAP/带 target 的 IAP 描述接口模式。最终成交属性还取决于盘口、有效方式与引擎规则。

## 三类自适应分别改变什么

| 机制 | 依据 | 改变对象 |
|---|---|---|
| LOW/HIGH 行情分组 | 波动／半价差统计 | K1、门槛或执行路径 |
| phase / section | watcher 发布值及附加条件 | 有效参数、交易对象或执行设置 |
| comm5 XS | 初始化时历史收益排名 | 金额倍率；另有零倍率动作门控 |
| SM4/TM6 候选选择 | 虚拟配对时长中位数 | 有效四阈值 |

这些机制分别维护状态，不合并为一个信号乘数。

## 限额与收益口径

新增敞口、净敞口、平仓量、金额、盘口可用量和保证金是不同约束。金额换算通常涉及 $A/(pM)$，最终还需保留原 min/max 顺序、浮点顺序和步长 mode。

watcher 值按发布者定义解释：订单回报收益累计、浮动收益或其他字段不能直接互换为账户净值。费用口径、预占和回报顺序尚需 SDK 端到端验证。
